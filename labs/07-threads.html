Before we start

Why this lab

Three workers update one shared counter at the same time. Will the final value always be correct?

Only if they take turns. This lab starts one IncrementThread and two DecrementRunnable threads on a shared Counter whose methods are synchronized.

Theory 1 of 5

Process and thread

  • A process has its own memory; threads inside it share the heap but each has its own stack.
  • Shared objects are convenient — and dangerous when several threads modify them.

Theory 2 of 5

Two ways to create a thread

class MyThread extends Thread {          // way 1
    @Override public void run() { ... }
}
new MyThread().start();

class MyTask implements Runnable {      // way 2
    @Override public void run() { ... }
}
new Thread(new MyTask()).start();
  • Runnable is usually preferred: your class can still extend another class, and the task is separate from the thread.

Theory 3 of 5

start() vs run()

thread.start();   // creates a new thread, which calls run()
thread.run();     // just a normal method call in the current thread
  • Only start() gives concurrent execution. Calling start() twice throws IllegalThreadStateException.

Theory 4 of 5

Java thread states

  • getState() returns the enum value. sleep(ms) puts a thread in TIMED_WAITING; waiting for a lock is BLOCKED.

Theory 5 of 5

sleep(), join() and synchronized

try {
    Thread.sleep(100);          // pause this thread
    worker.join();              // wait until worker finishes
} catch (InterruptedException e) {
    Thread.currentThread().interrupt();
}

public synchronized void increment() { value++; }
  • join() makes main wait so the final value is printed only after all workers finish.
  • synchronized lets one thread at a time run the method on the same object, preventing lost updates.

Implementation design

Program design

Implementation design

Execution flow

  1. Create a shared Counter at 0
  2. Create IncrementThread (3 increments) and two DecrementRunnable threads (3 and 2 decrements)
  3. Print every thread’s state: NEW
  4. start() all three and print states: RUNNABLE
  5. Each thread updates the counter and sleeps 100 ms
  6. main joins each thread
  7. Print the final value (3 increments, 5 decrements: −2) and the TERMINATED states

The message order changes between runs; synchronization keeps every individual update correct.

    private int iterations;

Code walkthrough 3 of 7 · IncrementThread.java

The work goes in run()

@Override
public void run() {
    for (int i = 0; i < iterations; i++) {
        counter.increment();
        try {
            Thread.sleep(100);
        } catch (InterruptedException e) {
            System.out.println(getName() + " was interrupted.");
            Thread.currentThread().interrupt();
            break;
        }
    }
    System.out.println(getName() + " finished.");
}
  • sleep(100) pauses so other threads get a turn.
  • If interrupted, restore the flag and stop.

public class Counter {

    private int value;
    private String name;

    public Counter(String name, int initialValue) {
        this.name = name;
        this.value = initialValue;
    }

    public synchronized void increment() {
        value++;
        System.out.println(Thread.currentThread().getName()
                + " incremented " + name + " to " + value);
    }

    public synchronized void decrement() {
        value--;
        System.out.println(Thread.currentThread().getName()
                + " decremented " + name + " to " + value);
    }

    public synchronized int getValue() {
        return value;
    }

    public void display() {
        System.out.println(name + " = " + getValue());
    }
}
public class IncrementThread extends Thread {

    private Counter counter;
    private int iterations;

    public IncrementThread(String name, Counter counter, int iterations) {
        super(name);
        this.counter = counter;
        this.iterations = iterations;
    }

    @Override
    public void run() {
        for (int i = 0; i < iterations; i++) {
            counter.increment();
            try {
                Thread.sleep(100);
            } catch (InterruptedException e) {
                System.out.println(getName() + " was interrupted.");
                Thread.currentThread().interrupt();
                break;
            }
        }
        System.out.println(getName() + " finished.");
    }
}
public class DecrementRunnable implements Runnable {

    private Counter counter;
    private int iterations;

    public DecrementRunnable(Counter counter, int iterations) {
        this.counter = counter;
        this.iterations = iterations;
    }

    @Override
    public void run() {
        for (int i = 0; i < iterations; i++) {
            counter.decrement();
            try {
                Thread.sleep(100);
            } catch (InterruptedException e) {
                System.out.println(Thread.currentThread().getName() + " was interrupted.");

                break;
            }
        }
        System.out.println(Thread.currentThread().getName() + " finished.");
    }
}
public class Lab7Demo {

    public static void main(String[] args) {

        // 1. Shared Counter Creation
        System.out.println("=== Thread Creation and Lifecycle Demo ===");
        Counter counter = new Counter("SharedCounter", 0);
        System.out.println("Initial counter state:");
        counter.display();

        // 2. Creating Threads
        System.out.println("\n=== Creating Threads ===");
        IncrementThread incrementThread = new IncrementThread("IncrementThread-1", counter, 3);
        DecrementRunnable decrementTask1 = new DecrementRunnable(counter, 3);
        DecrementRunnable decrementTask2 = new DecrementRunnable(counter, 2);
        Thread decrementThread1 = new Thread(decrementTask1, "DecrementThread-1");
        Thread decrementThread2 = new Thread(decrementTask2, "DecrementThread-2");

        System.out.println("IncrementThread-1 state: " + incrementThread.getState());
        System.out.println("DecrementThread-1 state: " + decrementThread1.getState());
        System.out.println("DecrementThread-2 state: " + decrementThread2.getState());

        // 3. Starting Threads
        System.out.println("\n=== Starting Threads ===");
        incrementThread.start();
        decrementThread1.start();
        decrementThread2.start();
        System.out.println("All threads started.");
        System.out.println("IncrementThread-1 state after start: " + incrementThread.getState());
        System.out.println("DecrementThread-1 state after start: " + decrementThread1.getState());
        System.out.println("DecrementThread-2 state after start: " + decrementThread2.getState());

        // 4. Waiting for Threads using join()
        System.out.println("\n=== Waiting for Threads to Complete ===");
        try {
            incrementThread.join();
            System.out.println("IncrementThread-1 has terminated.");
            decrementThread1.join();
            System.out.println("DecrementThread-1 has terminated.");
            decrementThread2.join();
            System.out.println("DecrementThread-2 has terminated.");
        } catch (InterruptedException e) {
            System.out.println("Main thread was interrupted.");
            Thread.currentThread().interrupt();
        }

        // 5. Final State
        System.out.println("\n=== Final State ===");
        counter.display();
        System.out.println("IncrementThread-1 final state: " + incrementThread.getState());
        System.out.println("DecrementThread-1 final state: " + decrementThread1.getState());
        System.out.println("DecrementThread-2 final state: " + decrementThread2.getState());
        System.out.println("All threads have completed.");
        System.out.println("Main thread exiting.");
    }
}

Viva questions (1 of 2)

What is the difference between start() and run()?
Show the answer
start() creates a new thread that calls run(); calling run() directly executes it in the current thread like any method.
Why is Runnable often preferred over extending Thread?
Show the answer
Java has single inheritance; implementing Runnable leaves the class free to extend another class and separates the task from the thread.

Summary

Summary

  • Threads share the heap but have their own stacks.
  • Create them by extending Thread or implementing Runnable; always call start().
  • States: NEW → RUNNABLE ⇄ TIMED_WAITING/BLOCKED/WAITING → TERMINATED.
  • sleep() pauses; join() waits for another thread.
  • synchronized methods keep shared data consistent.
