Mission 8 · Sharing safely

Your mission

Alpha and Bravo each score 100 000 points. The scoreboard says 145 000. Fifty-five thousand points vanished, and nobody cheated.

score = score + 1 is three steps, and two threads mixed them up: a race condition. synchronized lets one thread in at a time — but lock carelessly and two soldiers wait for each other forever: a deadlock.

Topic 1 of 6

Race condition

In the game:
Race condition: lost points
  • Two threads change the same variable at the same time.
  • count++ is three steps: read, add, write. Steps from two threads can mix.
  • Some updates are lost, and the result changes from run to run.

Topic 2 of 6

synchronized

In the game:
synchronized methods and blocks
public synchronized void addSafe(int points) {   // locks this Scoreboard
    score = score + points;
}

synchronized (ammoCrate) {                       // locks one chosen object
    // only one thread at a time in here
}
  • A synchronized method lets one thread in at a time; others wait for the lock.
  • A synchronized (obj) { … } block locks only the lines that need it.
  • Now no update is lost.
  • Every object has a lock (a monitor).

Scoreboard: unsafe and safe

// One scoreboard shared by the whole squad
public class Scoreboard {
    private int score = 0;

    // Not safe: read, add and write can interleave with another thread
    public void addUnsafe(int points) {
        score = score + points;
    }

    // Safe: only one thread at a time may run this method on this object
    public synchronized void addSafe(int points) {
        score = score + points;
    }

    public synchronized int getScore() {
        return score;
    }

    public synchronized void reset() {
        score = 0;
    }
}
  • addUnsafe has no lock: updates can be lost.
  • addSafe is synchronized on the scoreboard.

Topic 3 of 6

Deadlock

In the game:
Deadlock: two soldiers, two items
  • Two threads each hold one lock and wait for the other’s lock.
  • Neither can go on, so both wait forever.
  • In the game: the Medic holds the med kit and wants the crate; the Gunner holds the crate and wants the kit.

Topic 3 of 6 · our game program · 1 of 1 · SyncDemo.java

The soldier thread

static void pause(int ms) {
    try {
        Thread.sleep(ms);
    } catch (InterruptedException e) {
        Thread.currentThread().interrupt();
    }
}

// Each soldier needs both items; first and second say which lock is taken first
static Thread soldier(String name, Object first, String firstName, Object second, String secondName) {
    Thread t = new Thread(() -> {
        synchronized (first) {
            System.out.println("[" + name + "] has the " + firstName + ", wants the " + secondName);
            pause(100);
            synchronized (second) {
                System.out.println("[" + name + "] has both items: patched up and reloaded");
            }
        }
    }, name);
    t.setDaemon(true);                  // lets the program exit even if it gets stuck
    return t;
}
  • Each soldier locks first, then second.
  • Daemon threads let the program end even if they stay stuck.

Topic 4 of 6

The four conditions

In the game:
The four conditions and the graph
  • Mutual exclusion: a resource is held by one thread at a time.
  • Hold and wait: a thread keeps one resource while waiting for another.
  • No preemption: nobody can take a resource away. Circular wait: A waits for B, B waits for A.
  • All four together cause a deadlock; break any one to prevent it.

Topic 5 of 6

Preventing deadlock: lock order

In the game:
The fix: one lock order
// everyone locks the ammo crate first, then the med kit
synchronized (ammoCrate) {
    synchronized (medKit) {
        // patched up and reloaded
    }
}
  • Make every thread take the locks in the same order.
  • Then a circle of waiting can never form.
  • In the game: both soldiers take the ammo crate first, then the med kit.
  • If every thread takes locks in the same order, no cycle can form.

Topic 6 of 6

wait() and notifyAll()

In the game:
wait() and notifyAll(): supply drops
public synchronized void take() throws InterruptedException {
    while (crates == 0) {
        wait();               // release the lock and sleep
    }
    crates--;
}

public synchronized void drop(int count) {
    crates += count;
    notifyAll();              // wake every waiting soldier
}
  • wait() gives up the lock and sleeps until another thread calls notifyAll().
  • Call both inside synchronized code, and check the condition in a while loop.
  • Producer and consumer: one puts things in, the other takes them out.
  • wait() releases the lock while it waits; sleep() does not.

Topic 6 of 6 · our game program · 1 of 2 · SupplyDepot.java

SupplyDepot: wait and notifyAll

// Producer-consumer: a helicopter drops crates, soldiers take them
public class SupplyDepot {
    private int crates = 0;

    public synchronized void drop(int count) {
        crates += count;
        System.out.println("[" + Thread.currentThread().getName() + "] dropped " + count + " -> depot has " + crates);
        notifyAll();                        // wake everyone waiting for a crate
    }

    public synchronized void take() throws InterruptedException {
        String me = Thread.currentThread().getName();
        while (crates == 0) {
            System.out.println("[" + me + "] depot empty, waiting");
            wait();                         // releases the lock while waiting
        }
        crates--;
        System.out.println("[" + me + "] took a crate -> depot has " + crates);
    }
}
  • take() waits in a while loop until a crate exists.
  • drop() adds crates and wakes everyone.

public class BankAccount {

    private String accountId;
    private double balance;

    public BankAccount(String accountId, double initialBalance) {
        this.accountId = accountId;
        if (initialBalance >= 0.0) {
            this.balance = initialBalance;
        } else {
            this.balance = 0.0;
        }
    }

    public synchronized void withdraw(double amount) {
        if (amount <= 0.0) {
            throw new IllegalArgumentException("Amount must be positive.");
        }
        if (amount > balance) {
            throw new IllegalArgumentException("Insufficient funds in " + accountId
                    + ". Requested: " + amount + ", Available: " + balance);
        }
        balance = balance - amount;
        System.out.println(Thread.currentThread().getName() + " withdrew " + amount
                + " from " + accountId + ". New balance: " + balance);
    }

    public synchronized void deposit(double amount) {
        if (amount <= 0.0) {
            throw new IllegalArgumentException("Amount must be positive.");
        }
        balance = balance + amount;
        System.out.println(Thread.currentThread().getName() + " deposited " + amount
                + " into " + accountId + ". New balance: " + balance);
    }

    public synchronized double getBalance() {
        return balance;
    }

    public String getAccountId() {
        return accountId;
    }

    // Locks are acquired in a fixed order to prevent deadlock.
    public void transfer(BankAccount target, double amount) {
        if (target == null) {
            throw new IllegalArgumentException("Target account cannot be null.");
        }
        BankAccount first;
        BankAccount second;
        if (this.accountId.compareTo(target.accountId) < 0) {
            first = this;
            second = target;
        } else {
            first = target;
            second = this;
        }
        synchronized (first) {
            synchronized (second) {
                System.out.println(Thread.currentThread().getName() + " transferring "
                        + amount + " from " + this.accountId + " to " + target.accountId);
                this.withdraw(amount);
                target.deposit(amount);
                System.out.println(Thread.currentThread().getName() + " completed transfer.");
            }
        }
    }

    public void display() {
        System.out.println("Account: " + accountId + " | Balance: " + getBalance());
    }
}
public class DeadlockProneTransfer implements Runnable {

    private BankAccount from;
    private BankAccount to;
    private double amount;

    public DeadlockProneTransfer(BankAccount from, BankAccount to, double amount) {
        this.from = from;
        this.to = to;
        this.amount = amount;
    }

    // Inconsistent lock ordering: source first, then target.
    @Override
    public void run() {
        synchronized (from) {
            System.out.println(Thread.currentThread().getName() + " locked " + from.getAccountId());
            try {
                Thread.sleep(100);
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
            synchronized (to) {
                System.out.println(Thread.currentThread().getName() + " locked " + to.getAccountId());
                try {
                    from.withdraw(amount);
                    to.deposit(amount);
                    System.out.println(Thread.currentThread().getName() + " completed risky transfer.");
                } catch (IllegalArgumentException e) {
                    System.out.println("Risky transfer failed: " + e.getMessage());
                }
            }
        }
    }
}
public class Lab8Demo {

    public static void main(String[] args) {

        // 1. Creating Accounts
        System.out.println("=== Synchronization and Deadlock Demo ===");
        BankAccount account1 = new BankAccount("ACC-001", 5000.0);
        BankAccount account2 = new BankAccount("ACC-002", 3000.0);
        System.out.println("\n=== Initial Account States ===");
        account1.display();
        account2.display();

        // 2. Safe Transfer using Lock Ordering
        System.out.println("\n=== Safe Transfer using Lock Ordering ===");
        account1.transfer(account2, 1000.0);
        System.out.println("\nAfter safe transfer:");
        account1.display();
        account2.display();

        // 3. Concurrent Safe Transfers
        System.out.println("\n=== Concurrent Safe Transfers ===");
        BankAccount safeAccount1 = new BankAccount("ACC-001", 5000.0);
        BankAccount safeAccount2 = new BankAccount("ACC-002", 3000.0);

        Thread safeThread1 = new Thread(() -> {
            for (int i = 0; i < 5; i++) {
                safeAccount1.transfer(safeAccount2, 100.0);
                try {
                    Thread.sleep(50);
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                }
            }
        }, "SafeThread-1");

        Thread safeThread2 = new Thread(() -> {
            for (int i = 0; i < 5; i++) {
                safeAccount2.transfer(safeAccount1, 100.0);
                try {
                    Thread.sleep(50);
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                }
            }
        }, "SafeThread-2");

        safeThread1.start();
        safeThread2.start();
        try {
            safeThread1.join();
            safeThread2.join();
        } catch (InterruptedException e) {
            System.out.println("Main thread interrupted.");
            Thread.currentThread().interrupt();
        }
        System.out.println("\nAfter concurrent safe transfers:");
        safeAccount1.display();
        safeAccount2.display();
        double safeTotal = safeAccount1.getBalance() + safeAccount2.getBalance();
        System.out.println("Total balance: " + safeTotal);

        // 4. Deadlock Risk Demonstration
        System.out.println("\n=== Deadlock Risk Demonstration ===");
        System.out.println("The following example starts two risky transfer tasks.");
        System.out.println("If both threads remain alive after timeout, deadlock is possible.");
        BankAccount riskAccount1 = new BankAccount("ACC-001", 5000.0);
        BankAccount riskAccount2 = new BankAccount("ACC-002", 3000.0);
        Thread riskyThread1 = new Thread(
                new DeadlockProneTransfer(riskAccount1, riskAccount2, 500.0), "RiskyThread-1");
        Thread riskyThread2 = new Thread(
                new DeadlockProneTransfer(riskAccount2, riskAccount1, 700.0), "RiskyThread-2");
        riskyThread1.start();
        riskyThread2.start();
        try {
            riskyThread1.join(3000);
            riskyThread2.join(3000);
        } catch (InterruptedException e) {
            System.out.println("Main thread interrupted during deadlock test.");
            Thread.currentThread().interrupt();
        }
        if (riskyThread1.isAlive() || riskyThread2.isAlive()) {
            System.out.println("\nPossible deadlock detected.");
            System.out.println("At least one risky thread did not finish within timeout.");
            System.out.println("This happens because locks may be acquired in opposite order.");
        } else {
            System.out.println("\nRisky threads completed in this run.");
            System.out.println("Deadlock did not occur this time, but the design is unsafe.");
        }

        // 5. Final Message
        System.out.println("\n=== Final Observation ===");
        System.out.println("Use consistent lock ordering to prevent circular wait.");
        System.out.println("Program demonstration completed.");
    }
}

The object it is called on (this). Another thread calling any synchronized method of the same object must wait.

Summary

  • Shared data plus interleaving threads gives race conditions.
  • synchronized lets one thread at a time into a critical section.
  • Deadlock needs four conditions; circular wait is the easiest to break.
