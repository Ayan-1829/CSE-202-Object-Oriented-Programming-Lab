Before we start

Why this lab

Thread 1 moves money from A to B while thread 2 moves money from B to A. Each grabs one account and waits for the other — forever. How do we stop that?

That is a deadlock. In this lab you cause one on purpose, then remove it with a simple rule: always lock accounts in the same order.

Theory 1 of 6

Race conditions and critical sections

balance = balance + amount;   // read, add, write: three steps
  • If two threads interleave those steps, one update can overwrite the other — a race condition.
  • Code that touches shared data is a critical section; only one thread should run it at a time.

Theory 2 of 6

synchronized methods and blocks

public synchronized void deposit(double amount) { balance += amount; }

synchronized (account) {        // lock a chosen object
    account.withdraw(amount);
}
  • Entering either form acquires the object’s monitor lock; other threads wait (BLOCKED) until it is released.
  • Methods protect the whole body; blocks protect only what needs it and let you pick the lock — used to lock two accounts in transfer().

Theory 3 of 6

Deadlock

  • Four conditions must all hold: mutual exclusion, hold and wait, no preemption, circular wait.
  • Break any one of them and deadlock cannot happen.

Theory 4 of 6

Resource allocation graph

  • Threads are circles, resources are squares. Request edge: thread → resource; assignment edge: resource → thread.
  • A cycle in the graph means a possible deadlock.

Theory 5 of 6

Prevention: lock ordering

BankAccount first  = accountId.compareTo(target.accountId) < 0 ? this : target;
BankAccount second = (first == this) ? target : this;

synchronized (first) {
    synchronized (second) {
        this.withdraw(amount);
        target.deposit(amount);
    }
}
  • Every thread locks the account with the smaller ID first, so a circular wait is impossible.

Theory 6 of 6

wait(), notify() and notifyAll()

synchronized (buffer) {
    while (bufferIsEmpty) {
        buffer.wait();      // releases the lock while waiting
    }
    ...
    buffer.notifyAll();
}
  • Call them only while holding the object’s lock.
  • Always re-check the condition in a while loop: a woken thread may find the condition false again.

A synchronized withdrawal

public synchronized void withdraw(double amount) {
    if (amount <= 0.0) {
        throw new IllegalArgumentException("Amount must be positive.");
    }
    if (amount > balance) {
        throw new IllegalArgumentException("Insufficient funds in " + accountId
                + ". Requested: " + amount + ", Available: " + balance);
    }
    balance = balance - amount;
    System.out.println(Thread.currentThread().getName() + " withdrew " + amount
            + " from " + accountId + ". New balance: " + balance);
}
  • Check and update happen while holding the account’s lock.

Code walkthrough 2 of 9 · BankAccount.java

Choosing the lock order

// Locks are acquired in a fixed order to prevent deadlock.
public void transfer(BankAccount target, double amount) {
    if (target == null) {
        throw new IllegalArgumentException("Target account cannot be null.");
    }
    BankAccount first;
    BankAccount second;
    if (this.accountId.compareTo(target.accountId) < 0) {
        first = this;
        second = target;
    } else {
        first = target;
        second = this;
    }
  • The account with the smaller ID always becomes first, whichever direction the money moves.

Code walkthrough 3 of 9 · BankAccount.java

Locking both accounts in that order

synchronized (first) {
    synchronized (second) {
        System.out.println(Thread.currentThread().getName() + " transferring "
                + amount + " from " + this.accountId + " to " + target.accountId);
        this.withdraw(amount);
        target.deposit(amount);
        System.out.println(Thread.currentThread().getName() + " completed transfer.");
    }
}
  • Both locks are held during the whole transfer.
  • Two opposite transfers can never wait for each other in a circle.

Code walkthrough 4 of 9 · DeadlockProneTransfer.java

The risky way: lock the source

// Inconsistent lock ordering: source first, then target.
@Override
public void run() {
    synchronized (from) {
        System.out.println(Thread.currentThread().getName() + " locked " + from.getAccountId());
        try {
            Thread.sleep(100);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
  • Each thread locks its own source first, then sleeps while holding it.

Detecting it with a timeout

riskyThread1.start();
riskyThread2.start();
try {
    riskyThread1.join(3000);
    riskyThread2.join(3000);
} catch (InterruptedException e) {
    System.out.println("Main thread interrupted during deadlock test.");
    Thread.currentThread().interrupt();
}
if (riskyThread1.isAlive() || riskyThread2.isAlive()) {
    System.out.println("\nPossible deadlock detected.");
    System.out.println("At least one risky thread did not finish within timeout.");
    System.out.println("This happens because locks may be acquired in opposite order.");

    System.out.println("\nRisky threads completed in this run.");
    System.out.println("Deadlock did not occur this time, but the design is unsafe.");
}
  • join(3000) waits at most 3 s; a thread still alive means it is stuck.

The complete program

public class BankAccount {

    private String accountId;
    private double balance;

    public BankAccount(String accountId, double initialBalance) {
        this.accountId = accountId;
        if (initialBalance >= 0.0) {
            this.balance = initialBalance;
        } else {
            this.balance = 0.0;
        }
    }

    public synchronized void withdraw(double amount) {
        if (amount <= 0.0) {
            throw new IllegalArgumentException("Amount must be positive.");
        }
        if (amount > balance) {
            throw new IllegalArgumentException("Insufficient funds in " + accountId
                    + ". Requested: " + amount + ", Available: " + balance);
        }
        balance = balance - amount;
        System.out.println(Thread.currentThread().getName() + " withdrew " + amount
                + " from " + accountId + ". New balance: " + balance);
    }

    public synchronized void deposit(double amount) {
        if (amount <= 0.0) {
            throw new IllegalArgumentException("Amount must be positive.");
        }
        balance = balance + amount;
        System.out.println(Thread.currentThread().getName() + " deposited " + amount
                + " into " + accountId + ". New balance: " + balance);
    }

    public synchronized double getBalance() {
        return balance;
    }

    public String getAccountId() {
        return accountId;
    }

    // Locks are acquired in a fixed order to prevent deadlock.
    public void transfer(BankAccount target, double amount) {
        if (target == null) {
            throw new IllegalArgumentException("Target account cannot be null.");
        }
        BankAccount first;
        BankAccount second;
        if (this.accountId.compareTo(target.accountId) < 0) {
            first = this;
            second = target;
        } else {
            first = target;
            second = this;
        }
        synchronized (first) {
            synchronized (second) {
                System.out.println(Thread.currentThread().getName() + " transferring "
                        + amount + " from " + this.accountId + " to " + target.accountId);
                this.withdraw(amount);
                target.deposit(amount);
                System.out.println(Thread.currentThread().getName() + " completed transfer.");
            }
        }
    }

    public void display() {
        System.out.println("Account: " + accountId + " | Balance: " + getBalance());
    }
}
public class DeadlockProneTransfer implements Runnable {

    private BankAccount from;
    private BankAccount to;
    private double amount;

    public DeadlockProneTransfer(BankAccount from, BankAccount to, double amount) {
        this.from = from;
        this.to = to;
        this.amount = amount;
    }

    // Inconsistent lock ordering: source first, then target.
    @Override
    public void run() {
        synchronized (from) {
            System.out.println(Thread.currentThread().getName() + " locked " + from.getAccountId());
            try {
                Thread.sleep(100);
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
            synchronized (to) {
                System.out.println(Thread.currentThread().getName() + " locked " + to.getAccountId());
                try {
                    from.withdraw(amount);
                    to.deposit(amount);
                    System.out.println(Thread.currentThread().getName() + " completed risky transfer.");
                } catch (IllegalArgumentException e) {
                    System.out.println("Risky transfer failed: " + e.getMessage());
                }
            }
        }
    }
}
public class Lab8Demo {

    public static void main(String[] args) {

        // 1. Creating Accounts
        System.out.println("=== Synchronization and Deadlock Demo ===");
        BankAccount account1 = new BankAccount("ACC-001", 5000.0);
        BankAccount account2 = new BankAccount("ACC-002", 3000.0);
        System.out.println("\n=== Initial Account States ===");
        account1.display();
        account2.display();

        // 2. Safe Transfer using Lock Ordering
        System.out.println("\n=== Safe Transfer using Lock Ordering ===");
        account1.transfer(account2, 1000.0);
        System.out.println("\nAfter safe transfer:");
        account1.display();
        account2.display();

        // 3. Concurrent Safe Transfers
        System.out.println("\n=== Concurrent Safe Transfers ===");
        BankAccount safeAccount1 = new BankAccount("ACC-001", 5000.0);
        BankAccount safeAccount2 = new BankAccount("ACC-002", 3000.0);

        Thread safeThread1 = new Thread(() -> {
            for (int i = 0; i < 5; i++) {
                safeAccount1.transfer(safeAccount2, 100.0);
                try {
                    Thread.sleep(50);
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                }
            }
        }, "SafeThread-1");

        Thread safeThread2 = new Thread(() -> {
            for (int i = 0; i < 5; i++) {
                safeAccount2.transfer(safeAccount1, 100.0);
                try {
                    Thread.sleep(50);
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                }
            }
        }, "SafeThread-2");

        safeThread1.start();
        safeThread2.start();
        try {
            safeThread1.join();
            safeThread2.join();
        } catch (InterruptedException e) {
            System.out.println("Main thread interrupted.");
            Thread.currentThread().interrupt();
        }
        System.out.println("\nAfter concurrent safe transfers:");
        safeAccount1.display();
        safeAccount2.display();
        double safeTotal = safeAccount1.getBalance() + safeAccount2.getBalance();
        System.out.println("Total balance: " + safeTotal);

        // 4. Deadlock Risk Demonstration
        System.out.println("\n=== Deadlock Risk Demonstration ===");
        System.out.println("The following example starts two risky transfer tasks.");
        System.out.println("If both threads remain alive after timeout, deadlock is possible.");
        BankAccount riskAccount1 = new BankAccount("ACC-001", 5000.0);
        BankAccount riskAccount2 = new BankAccount("ACC-002", 3000.0);
        Thread riskyThread1 = new Thread(
                new DeadlockProneTransfer(riskAccount1, riskAccount2, 500.0), "RiskyThread-1");
        Thread riskyThread2 = new Thread(
                new DeadlockProneTransfer(riskAccount2, riskAccount1, 700.0), "RiskyThread-2");
        riskyThread1.start();
        riskyThread2.start();
        try {
            riskyThread1.join(3000);
            riskyThread2.join(3000);
        } catch (InterruptedException e) {
            System.out.println("Main thread interrupted during deadlock test.");
            Thread.currentThread().interrupt();
        }
        if (riskyThread1.isAlive() || riskyThread2.isAlive()) {
            System.out.println("\nPossible deadlock detected.");
            System.out.println("At least one risky thread did not finish within timeout.");
            System.out.println("This happens because locks may be acquired in opposite order.");
        } else {
            System.out.println("\nRisky threads completed in this run.");
            System.out.println("Deadlock did not occur this time, but the design is unsafe.");
        }

        // 5. Final Message
        System.out.println("\n=== Final Observation ===");
        System.out.println("Use consistent lock ordering to prevent circular wait.");
        System.out.println("Program demonstration completed.");
    }
}

Viva questions (2 of 2)

Why does transfer() use synchronized blocks rather than a synchronized method?
Show the answer
It needs to hold two different objects’ locks, chosen in a specific order; a synchronized method locks only this.
Why must wait() be inside a while loop?
Show the answer
A woken thread may find the condition false again (another thread got there first, or a spurious wake-up), so it must re-check.

Summary

Summary

  • Shared data + concurrent writes = race conditions; protect critical sections.
  • synchronized methods and blocks take an object’s monitor lock.
  • Deadlock needs mutual exclusion, hold and wait, no preemption and circular wait.
  • Consistent lock ordering removes circular wait.
  • wait/notify/notifyAll coordinate threads; always wait in a while loop.
