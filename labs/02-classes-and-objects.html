Before we start

Why this lab

A car park holds hundreds of cars, all different, all built to one design. How does a program describe the design once and make many cars?

The design is a class; each car is an object with its own make, speed and fuel. In this lab you build a Car class and drive two of them.

Theory 1 of 5

Class and object

  • A class is a blueprint: it lists the data (fields) and actions (methods) every object will have.
  • An object is a runtime instance made with new; each one has its own copy of the fields.

Theory 2 of 5

Fields, constructor and this

public class Car {
    private String make;
    private int speed;
    private double fuelLevel;

    public Car(String make, double fuelLevel) {
        this.make = make;          // field = parameter
        this.speed = 0;
        this.fuelLevel = fuelLevel;
    }
}
  • A constructor has the class name and no return type; it runs once, when the object is created.
  • this.make is the field of the current object; make alone is the parameter.

Theory 3 of 5

Encapsulation: getters and validating setters

public void setFuelLevel(double fuelLevel) {
    if (fuelLevel >= 0.0 && fuelLevel <= 100.0) {
        this.fuelLevel = fuelLevel;   // invalid values are rejected
    }
}
  • Fields are private: outside code cannot change them directly.
  • Public methods give controlled access, so an object can never hold an invalid fuel level.

Theory 4 of 5

Instance members vs static members

  • Each object has its own make, speed and fuelLevel.
  • private static int count belongs to the class: one copy shared by all cars.
  • Call a static method on the class: Car.getCount().

Theory 5 of 5

References, stack and heap

  • Objects live on the heap; variables on the stack hold references to them.
  • Assigning a reference copies the arrow, not the object: car1 and car3 are aliases.

References, stack and heap

Car car3 = car1;      // no new object!
car3.accelerate(20);
System.out.println(car1.getSpeed());  // changed too

Program design

Implementation design

Execution flow

  1. Create two Car objects; the constructor increments the static count
  2. Print the count with Car.getCount()
  3. Accelerate and brake car1, showing state after each call (speed never goes below 0)
  4. Accelerate and refuel car2 (fuel never exceeds 100)
  5. Read with getters, change make with a setter
  6. Alias car3 = car1 and show the shared speed
  7. Print the final count

Car defines state and behaviour; Lab2Demo only tests it.

public void brake(int delta) {

  • Math.max(0, …) keeps the speed from going negative.

The complete program

public class Car {

    // Private instance fields
    private String make;
    private int speed;
    private double fuelLevel;

    // Static field shared by all Car objects
    private static int count = 0;

    public Car(String make, double fuelLevel) {
        this.make = make;
        this.speed = 0;
        if (fuelLevel >= 0.0 && fuelLevel <= 100.0) {
            this.fuelLevel = fuelLevel;
        } else {
            this.fuelLevel = 0.0;
        }
        count++;
    }

    public void accelerate(int delta) {
        if (delta > 0) {
            this.speed = this.speed + delta;
        }
    }

    public void brake(int delta) {
        if (delta > 0) {
            this.speed = Math.max(0, this.speed - delta);
        }
    }

    public void refuel(double amount) {
        if (amount > 0.0) {
            this.fuelLevel = Math.min(100.0, this.fuelLevel + amount);
        }
    }

    public void display() {
        System.out.println("-------------------------------");
        System.out.println("Make      : " + make);
        System.out.println("Speed     : " + speed + " km/h");
        System.out.printf("Fuel Level: %.1f%%%n", fuelLevel);
        System.out.println("-------------------------------");
    }

    // Getter methods
    public String getMake() { return make; }
    public int getSpeed() { return speed; }
    public double getFuelLevel() { return fuelLevel; }

    // Setter methods
    public void setMake(String make) { this.make = make; }

    public void setFuelLevel(double fuelLevel) {
        if (fuelLevel >= 0.0 && fuelLevel <= 100.0) {
            this.fuelLevel = fuelLevel;
        }
    }

    // Static method
    public static int getCount() { return count; }
}

Discussion and analysis

Viva questions (1 of 2)

Why are the fields of Car private?
Show the answer
Encapsulation: only Car’s own methods can change them, so rules such as “speed never below 0” and “fuel 0–100” are always enforced.
Why is count static but speed is not?
Show the answer
count describes the class (how many cars exist) and must be shared; speed describes one particular car.

Summary

  • A class is a blueprint; objects are instances created with new.
  • Constructors initialise objects; this names the current object.
  • Private fields + public methods = encapsulation and validation.
  • Static fields and methods belong to the class and are shared.
  • Variables hold references: assignment creates aliases, not copies.
