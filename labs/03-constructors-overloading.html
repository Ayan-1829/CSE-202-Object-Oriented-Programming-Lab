Before we start

Why this lab

You pass a rectangle to a method and it comes back twice as big. You pass a number and it comes back unchanged. Why the difference?

Java always passes a copy: a copy of the number, or a copy of the reference to the object. This lab proves it with a Rectangle class.

Theory 1 of 5

Default, parameterised and copy constructors

public Rectangle()                         // default: 1 x 1, White
public Rectangle(double side)              // square
public Rectangle(double w, double h)       // rectangle
public Rectangle(double w, double h, String colour)
public Rectangle(Rectangle other)          // copy
  • Java writes a no-argument constructor only if you write none yourself.
  • A copy constructor builds a new, independent object with the same field values.

Constructor chaining with this(…)

  • Simpler constructors delegate to the full one, so validation lives in one place.

Theory 3 of 5

Method overloading

public double area()                                   // own fields
public double area(double scaleFactor)                 // scaled
public static double area(double width, double height) // any size
  • Same name, different parameter lists (number, type or order).
  • Resolved by the compiler at compile time.
  • A different return type or access modifier alone is not an overload — compile error.

Theory 4 of 5

Passing a primitive

  • The method gets a copy of the value; changing the copy cannot touch the caller’s variable.

Passing a primitive

static void passPrimitive(double side) { side = side * 2; }

double side = 10.0;
passPrimitive(side);   // side is still 10.0

Theory 5 of 5

Passing an object reference

  • The method gets a copy of the reference: both point to the same object, so r.scale(2.0) is visible to the caller.
  • Reassigning the parameter (r = new Rectangle(…)) only moves the copy; the caller still sees the original.
  • So Java is always pass-by-value — for objects the value is a reference.

Three overloads of area()

public double area() {
    return width * height;
}

public double area(double scaleFactor) {
    return area() * scaleFactor;
}

    return width * height;

The complete program

public class Rectangle {

    private double width;
    private double height;
    private String colour;

    public Rectangle() {
        this(1.0, 1.0, "White");
    }

    public Rectangle(double side) {
        this(side, side, "White");
    }

    public Rectangle(double width, double height) {
        this(width, height, "White");
    }

    public Rectangle(double width, double height, String colour) {
        if (width > 0) {
            this.width = width;
        } else {
            this.width = 1.0;
        }
        if (height > 0) {
            this.height = height;
        } else {
            this.height = 1.0;
        }
        this.colour = colour;
    }

    // Copy constructor
    public Rectangle(Rectangle other) {
        this(other.width, other.height, other.colour);
    }

    public double area() {
        return width * height;
    }

    public double area(double scaleFactor) {
        return area() * scaleFactor;
    }

    public static double area(double width, double height) {
        return width * height;
    }

    public String describe() {
        return String.format("Rectangle[%.2f x %.2f, colour=%s, area=%.2f]",
                width, height, colour, area());
    }

    public String describe(String prefix) {
        return prefix + ": " + describe();
    }

    public void scale(double factor) {
        if (factor > 0) {
            width = width * factor;
            height = height * factor;
        }
    }

    public double getWidth() { return width; }
    public double getHeight() { return height; }
    public String getColour() { return colour; }
    public void setColour(String colour) { this.colour = colour; }

    @Override
    public String toString() {
        return describe();
    }
}

Viva questions (1 of 2)

Why must this(…) be the first statement in a constructor?
Show the answer
The object must be fully initialised by the delegated constructor before any other code runs; Java enforces it at compile time.
Can two methods differ only in return type?
Show the answer
No. The call calculate() would be ambiguous, so it is a compile error.

Discussion and analysis

Viva questions (2 of 2)

Is Java pass-by-reference for objects?
Show the answer
No. It passes the reference by value: mutation through the copy is visible, but reassigning the parameter is not.
When does a copy constructor fail to give independence?
Show the answer
When a field is itself a reference (such as an array) and only the reference is copied — a shallow copy. Copy the array too for a deep copy.

Summary

  • Default, parameterised and copy constructors give flexible object creation.
  • Chain constructors with this(…) so validation lives in one place.
  • Overloads share a name but differ in parameters; the compiler chooses.
  • Java passes copies: of values for primitives, of references for objects.
  • Mutation through a reference is visible; reassigning the parameter is not.
