General information

CourseCSE 202 · Object Oriented Programming Lab · laboratory course
LanguageJava (JDK with NetBeans or another IDE)
Companion theoryCSE 201 Object Oriented Programming
MaterialsTen interactive chapters that build one Java game, Code Commando, plus the official lab programs and tasks

How each chapter works

Each chapter follows the same plan: the topic explained through Code Commando, the game built during the course; the chapter’s game program walked through section by section with its real output; game practice tasks; then the official lab program, its in-lab tasks and the report exercises from the lab manual.

Lab plan

LabChapterSlides
IJava Syntax, Data Types & Control Flow
Meet Code Commando, the game we build this semester. Start with its numbers: variables and types for health, ammo and score, a cast for damage, if and switch for decisions, and loops for firing.		Open
IIClasses, Objects, Instances & Methods
Turn the commando and the drones into objects. One class is the blueprint, every object keeps its own health. Fields, constructors, methods, encapsulation, static members and references.		Open
IIIConstructors, Overloading & Reference Passing
Build an armory: default, parameterised and copy constructors for Weapon, chaining with this(…), an overloaded shoot(), and what really happens when you pass an int or a Weapon to a method.		Open
IVInheritance, Polymorphism & Overriding
Drones, tanks and snipers are all enemies, and enemies and the player are all game characters. Inheritance shares the common code, overriding gives each enemy its own attack, and polymorphism runs a whole wave with one loop.		Open
VAbstract Classes & Interfaces
Everything on screen is a GameObject that must update() itself and say how it looks, yet nobody can create a plain GameObject. Interfaces add abilities across the tree: Damageable, Shooter and Collectible.		Open
VIException Handling & Custom Exceptions
A gun runs out of ammo, a player types a level that does not exist, a lane number is out of range. Exceptions let the game notice the problem, deal with it and keep running.		Open
VIIThread Creation & Thread States
In a real game the enemy spawner, the ammo regeneration and the countdown timer all run at the same time. Each one is a thread. Create threads two ways, start them, watch their states and wait for them with join().		Open
VIIISynchronization, Deadlock & Resource Allocation
The squad shares one scoreboard, one ammo crate and one med kit. Without care, points get lost and soldiers freeze. Race conditions, synchronized, deadlock and its fix, and wait/notify for supply drops.		Open
IXGUI Components, Drawing, AWT & Swing
Leave the console behind. A JFrame window, a score label, Fire and Reset buttons, and a JPanel that draws the commando and the drones from rectangles and ovals, then reacts to the keyboard.		Open
XAnimation with Threads
The finished game. A game-loop thread updates every object about 60 times a second, Rectangle collisions decide what is hit, drones bob, tanks fire shells, and Swing paints each frame. Every chapter so far comes together here.		Open

Lab exercises at the end of every lab are submitted as a lab report.
